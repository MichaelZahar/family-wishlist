# Family Wishlist — план реализации

Снимок от 2026-11-03. ⚠️ Объём и нумерация фич устарели: источник истины — `docs/prd.md` (раздел 8). Обновление плана — TBD.

## 1. Цель и рамки

**Главная цель** — отработанный процесс: spec-driven development (SDD) + мультиагентная разработка в Claude Code, доведённая до боевого деплоя. Каждая фаза заканчивается артефактом и выводом о процессе.

**Разделение инструментов:**

| Где | Что делаем |
| --- | --- |
| claude.ai Project | Продуктовая и архитектурная документация: PRD, доменная модель, NFR, ADR, конституция, feature briefs |
| Репозиторий | Источник истины для кода и рабочих спек: `/docs`, `/specs`, `CLAUDE.md` |
| Claude Code | Детализация спек, планы, задачи, реализация, тесты, ревью, деплой |

Документ рождается в Project, после утверждения переезжает в репозиторий и дальше живёт там.

## 2. Технический стек

См. ADR-001 (стек), ADR-003 (auth) в `docs/adr.md`.

## 3. Хостинг

См. ADR-002: Railway, один сервис отдаёт API и React, Postgres в том же проекте. Дополнительно: Sentry (ошибки), UptimeRobot (мониторинг), Resend или аналог (email, PRD F10).

## 4. Development flow: SDD + мультиагентность

### 4.1 Цикл фичи (Spec Kit)

| Шаг | Артефакт | Кто | Гейт |
| --- | --- | --- | --- |
| 0. Constitution (один раз) | `memory/constitution.md` | Ты + Claude (Project) | Утверждение |
| 1. Specify | `specs/NNN-feature/spec.md`: user stories, acceptance criteria | Claude Code по brief | ✅ Ревью спеки |
| 2. Clarify | Вопросы и ответы в спеке | Агент + ты | — |
| 3. Plan | `plan.md`, `data-model.md`, `contracts/` | `architect` | ✅ Ревью плана |
| 4. Tasks | `tasks.md` с пометками параллельности | Агент | Проверка |
| 5. Analyze | Согласованность spec ↔ plan ↔ tasks | Агент | — |
| 6. Implement | Код + тесты, PR | Субагенты | ✅ Ревью PR |
| 7. Verify | Acceptance criteria, e2e | QA-агент + ты | Merge |

**Эксперимент по методологиям:** первые фичи — Spec Kit; следующие — OpenSpec (спеки вокруг изменений, archive дельт); далее — собственные skills из лучшего. Сравнение в ретро: ручные правки, итерации, время, соответствие кода спеке.

### 4.2 Роли агентов (`.claude/agents/*.md`)

| Агент | Зона | Не делает |
| --- | --- | --- |
| `architect` | План, модель данных, контракты, ADR | Не пишет продуктовый код |
| `backend-dev` | `apps/api`, миграции | Не трогает `apps/web` |
| `frontend-dev` | `apps/web` | Не меняет контракт без `architect` |
| `test-engineer` | Тесты по acceptance criteria, до реализации | Не правит прод-код под тест |
| `reviewer` | Дифф против спеки и конституции | Не редактирует |
| `security-reviewer` | Auth, права, утечки броней, OWASP | Не редактирует |

Оркестратор — главная сессия Claude Code. Каждая фича — отдельная ветка и git worktree. Контракт в `packages/shared` замораживается до implement.

Прогрессия: одиночный агент (baseline) → субагенты под оркестратором → параллельные worktree + автоматическое PR-ревью в CI.

### 4.3 Гейты в Claude Code

- `CLAUDE.md` в корне, `apps/api`, `apps/web`.
- Hooks: форматирование после правки; `lint`, `typecheck`, `test` перед завершением; запрет правки `.env` и прод-миграций.
- Skills: `/new-feature`, `/verify-spec`, `/adr`, `/release`.
- MCP: GitHub, Playwright, Postgres (только локальная БД).
- Allowlist команд в `.claude/settings.json`; деструктивные операции и деплой — с подтверждением.

### 4.4 Журнал эксперимента

`docs/process-log.md` — запись на фичу: методология, конфигурация агентов, время, итерации, ручные правки, находки ревьюера, выводы.

## 5. Фазы

| Фаза | Срок | Содержание | Готово, когда |
| --- | --- | --- | --- |
| 0. Решения | 1–2 дня | Продуктовые вопросы, ADR-001…004 ✅; репо ✅, аккаунты Railway, Sentry | ADR приняты, аккаунты есть |
| 1. Документация | 3–5 дней | PRD ✅ (ядро), доменная модель, матрица прав, NFR, архитектура, конституция, feature briefs | Документы в `/docs` |
| 2. Окружение | 2–3 дня | Монорепо, Docker Compose с Postgres, скрипты, GitHub Actions, Claude Code (агенты, hooks, skills), Spec Kit, защита `main` | Клон поднимается одной командой, CI зелёный |
| 3. Walking skeleton | 1–2 дня | `GET /api/health` + страница React, миграция, деплой на Railway, домен, Sentry, UptimeRobot | Каждый merge в `main` уходит в прод |
| 4. Фичи | 6–7 недель | Вертикальные срезы по SDD-циклу; ретро после каждой фичи | MVP из PRD готов |
| 5. Hardening | 3–5 дней | Rate limit, CSRF, helmet, IDOR, SSRF, аудит зависимостей, бэкапы, логи, a11y | Чек-лист пройден |
| 6. Запуск и ретро | 1–2 дня | Приглашение семьи, итоговое ретро, шаблон репозитория | Ретро записано |

## 6. Риски

| Риск | Митигация |
| --- | --- |
| Спеки и код расходятся | `/verify-spec` в каждом PR; правка спеки — часть изменения поведения |
| Агенты ломают границы модулей | Узкие зоны, отдельные `CLAUDE.md`, ревью диффа по путям |
| Утечка брони владельцу | Строка в матрице прав, e2e-тест, security-review брони |
| SSRF при разборе ссылок | Запрет внутренних адресов, таймауты, лимит размера, без JS |
| Злоупотребления гостевыми бронями | Rate limit, отмена владельцем или admin |
| Рост счёта Railway; бэкапы на нас | Лимит расходов; ежедневный `pg_dump`, проверка восстановления |
| Overhead процесса | Baseline на первой фиче; облегчённый режим для мелких задач |
