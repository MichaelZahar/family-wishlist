# F1 · Auth и семья — feature brief

Статус: утверждён · 2026-11-12 · Приоритет: Must · Методология: Spec Kit (baseline, один агент)
Вход для `/specify`. Правила `R-AUTH-…` — в `prd.md`, раздел 5.

## Суть

Человек создаёт семью и становится admin, приглашает взрослых по ссылке; участники входят по email и паролю.

## Объём

**Входит:**

- Регистрация с созданием семьи.
- Приглашение по ссылке: выпуск, отзыв неиспользованного, принятие.
- Вход, выход, сессии.
- Ссылка сброса пароля, выпускаемая admin.
- Профиль взрослого: создаётся при вступлении; имя и язык интерфейса.

**Не входит:**

| Что | Где |
| --- | --- |
| Детские профили | F8 |
| Смена ролей, удаление участников, список приглашений | F7 |
| Вход через Google | F13 |
| Email-доставка приглашений и сброса | F10 |
| Несколько семей на аккаунт | F12 |

## Правила

- **R-AUTH-01.** Пользователь МОЖЕТ зарегистрироваться без приглашения, только создав новую семью; он становится admin этой семьи.
- **R-AUTH-02.** Когда admin создаёт приглашение, система ДОЛЖНА выдать одноразовую ссылку со сроком 7 дней (ADR-003).
- **R-AUTH-03.** Когда человек открывает действующее приглашение и задаёт email, пароль и имя, система ДОЛЖНА создать аккаунт с ролью member и взрослый профиль в семье.
- **R-AUTH-04.** Если приглашение истекло, использовано или отозвано, система ДОЛЖНА отказать и предложить запросить новое у admin.
- **R-AUTH-05.** Если по приглашению приходит пользователь, уже состоящий в семье, система ДОЛЖНА отказать (до F12).
- **R-AUTH-06.** admin МОЖЕТ отозвать неиспользованное приглашение.
- **R-AUTH-07.** Пользователь МОЖЕТ войти по email и паролю и выйти. Сессия — 30 дней со скользящим продлением (ADR-003).
- **R-AUTH-08.** admin МОЖЕТ выпустить ссылку сброса пароля для участника; срок 24 ч, одноразовая. После сброса все сессии участника ДОЛЖНЫ завершиться.
- **R-AUTH-09.** Пользователь МОЖЕТ изменить отображаемое имя и язык интерфейса (`ru`/`en`, N-UX-04).
- **R-AUTH-10.** Пароль: ≥ 10 символов, без требований к составу.

Связанные: N-SEC-04…07, N-SEC-13, N-PRV-03, D-01, D-06, ADR-003, ADR-004, `permissions.md` («Семья»).

## Acceptance criteria

**AC-1. Создание семьи**
- Given: нет аккаунта.
- When: регистрируюсь с email, паролем, именем и названием семьи.
- Then: создан аккаунт, семья, профиль; я admin; я вошёл.

**AC-2. Приглашение**
- Given: я admin.
- When: создаю приглашение.
- Then: получаю ссылку; она действует 7 дней и одноразовая.

**AC-3. Вступление по приглашению**
- Given: действующая ссылка приглашения.
- When: открываю её и регистрируюсь.
- Then: я member этой семьи с собственным профилем; ссылка больше не работает.

**AC-4. Недействительное приглашение**
- Given: ссылка истекла, использована или отозвана.
- When: открываю её.
- Then: вижу отказ с подсказкой обратиться к admin; аккаунт не создан.

**AC-5. Права на приглашения**
- Given: я member.
- When: пытаюсь создать или отозвать приглашение через UI или API.
- Then: `403`; приглашение не создано.

**AC-6. Вход и выход**
- Given: аккаунт существует.
- When: ввожу верные данные → выхожу.
- Then: вхожу в свою семью; после выхода защищённые страницы недоступны.

**AC-7. Неверный вход и rate limit**
- Given: аккаунт существует.
- When: 6 неверных попыток за минуту.
- Then: 6-я → `429`; ответы не раскрывают, существует ли email (N-SEC-07).

**AC-8. Сброс пароля через admin**
- Given: я admin, участник забыл пароль.
- When: выпускаю ссылку сброса → участник задаёт новый пароль.
- Then: участник входит с новым паролем; старые сессии завершены; ссылка больше не работает.

**AC-9. Изоляция семей**
- Given: две семьи.
- When: admin семьи А обращается к приглашениям и участникам семьи Б через API.
- Then: `404`; данные не раскрыты (D-01, N-SEC-02).

**AC-10. Язык**
- Given: я вошёл.
- When: меняю язык на `en`.
- Then: интерфейс на английском, настройка сохраняется между сессиями.

## Зависимости

- Фаза 2 завершена: монорепо, Postgres, CI, i18n-каркас.
- Better Auth + плагин `organization` + Drizzle-адаптер (ADR-003).
- Сущности: Family, Profile (`domain-model.md`).

## Решения

- ✅ Q-18 → А: открытая регистрация с созданием своей семьи (R-AUTH-01).
- ✅ Q-19 → А: пароль ≥ 10 символов, без правил состава (R-AUTH-10). Проверка по базе утёкших паролей — кандидат в фазу 5.
