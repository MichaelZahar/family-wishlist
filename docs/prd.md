# Family Wishlist — PRD

Статус: ядро утверждено, открытые вопросы Q-01…Q-06 закрыты · 2026-11-12

## 1. Проблема

- Желания разбросаны по головам и чатам → родственники дарят дубли.
- Чтобы угадать подарок, спрашивают напрямую → сюрприз теряется.
- Один общий список не подходит: мужу, друзьям и детям нужны разные подборки желаний, а часть дарящих (друзья, дальние родственники) не пользуется приложением.

## 2. Решение

Личный пул желаний → вишлисты-подборки для конкретных получателей → тайная бронь подарков.

## 3. Глоссарий

| Термин | Определение |
| --- | --- |
| **Профиль** | Член семьи, владелец пула. Взрослый (с логином) или детский (без логина) |
| **Желание** | Вещь или идея, которую профиль хочет получить. Конкретное — со ссылкой; абстрактное — без ссылки |
| **Пул желаний** | Все желания профиля. Видят владелец и управляющий взрослый детского профиля |
| **Вишлист** | Подборка желаний из пула. Примеры: «Для мужа», «Для друзей», «Для детей» |
| **Получатель** | Тот, кому открыт вишлист: пользователь (шаринг) или гость (ссылка) |
| **Бронь** | Отметка дарящего «подарю я». Ставится на желание, не на вишлист |
| **Событие** | Дата повода: день рождения, праздник, годовщина |

## 4. Роли

| Роль | Кто | Права |
| --- | --- | --- |
| admin | Организатор семьи | Права member + приглашения, роли, удаление участников, детские профили |
| member | Взрослый член семьи | Свой пул и вишлисты, шаринг, бронь |
| Детский профиль | Ребёнок | Нет логина; ведёт управляющий взрослый |
| Гость | Внешний человек по ссылке | Просмотр вишлиста, бронь с именем (R-RES-04) |

## 5. Правила

**Желания**

- **R-WSH-01.** Пользователь МОЖЕТ создать желание по ссылке или вручную.
- **R-WSH-02.** Когда пользователь вставляет ссылку, система ДОЛЖНА заполнить название, цену, картинку, магазин.
- **R-WSH-03.** Если разбор не удался, система ДОЛЖНА сохранить ссылку и открыть поля для ручного ввода.

**Вишлисты и доступ**

- **R-LST-01.** Пользователь МОЖЕТ создавать, редактировать, удалять вишлисты.
- **R-LST-02.** Желание МОЖЕТ входить в несколько вишлистов.
- **R-LST-03.** Пока вишлист никому не открыт, его видит только владелец.
- **R-LST-04.** Владелец МОЖЕТ открыть вишлист конкретным пользователям и/или по ссылке.
- **R-LST-05.** Владелец МОЖЕТ отозвать доступ, включая ссылку.

**Брони**

- **R-RES-01.** Система НЕ ДОЛЖНА показывать владельцу желания факт, автора и время брони.
- **R-RES-02.** Когда желание забронировано, система ДОЛЖНА показывать «занято» во всех вишлистах с этим желанием.
- **R-RES-03.** admin видит брони в чужих вишлистах. R-RES-01 приоритетнее для его собственных.
- **R-RES-04.** Гость МОЖЕТ забронировать желание по ссылке, указав имя; аккаунт не требуется.
- **R-RES-05.** Система ДОЛЖНА показывать гостю «занято» на забронированных желаниях, без имени дарящего.
- **R-RES-06.** У желания НЕ ДОЛЖНО быть больше одной активной брони.
- **R-RES-07.** Когда владелец удаляет забронированное желание или убирает его из вишлиста, система ДОЛЖНА сохранить бронь в списке броней дарящего с пометкой «удалено».

**Лента, события, история**

- **R-FEED-01.** Система ДОЛЖНА показывать получателю ленту изменений открытых ему вишлистов. Брони в ленте не раскрываются владельцу.
- **R-EVT-01.** Перед событием система ДОЛЖНА напомнить получателю внутри приложения и дать ссылку на вишлист события. Сроки: за 14 и за 3 дня.
- **R-HIS-01.** После даты события система ДОЛЖНА перевести вишлист в архив, а забронированные желания — в статус «подарено».

## 6. Сценарии

1. Конкретное желание: ссылка → автозаполнение → правка → пул.
2. Абстрактное желание: «Поездка в Абу-Даби» + описание, бюджет, приоритет → пул.
3. Вишлист для мужа: желания из пула → открыть мужу.
4. Вишлист для друзей: включить ссылку → отправить в мессенджер.
5. Получатель: открытые мне вишлисты, лента, напоминания о событиях.
6. Бронь: открыть вишлист → забронировать свободное желание.
7. Ребёнок: переключиться на детский профиль → вести его пул и вишлисты.
8. После события: вишлист в архиве, подаренное отмечено.

## 7. Метрики

| Цель | Метрика | Цель MVP |
| --- | --- | --- |
| Использование | Взрослые с ≥ 1 открытым вишлистом | ≥ 70% взрослых через месяц после запуска (TBD: подтвердить) |
| Автозаполнение | Ссылки с заполненными названием и картинкой | ≥ 70% |
| Без дублей | Желания, подаренные дважды | 0 |
| Сюрприз | Утечки броней владельцу | 0 |
| Вне семьи | Вишлисты, открытые по ссылке | ≥ 1 к ближайшему празднику |

## 9. Non-goals

- Покупки, корзины, комиссии.
- Отслеживание цен и скидок.
- Сбор денег на подарок.
- Публичная лента, лайки, комментарии, поиск людей.
- Аккаунты для гостей.
- Нативные мобильные приложения.
- Парсеры под конкретные магазины.

## 10. Решённые вопросы

- ✅ Q-01 → гость бронирует с именем, без аккаунта (R-RES-04).
- ✅ Q-02 → гость видит «занято» без имени дарящего (R-RES-05).
- ✅ Q-03 → одно желание — одна бронь (R-RES-06).
- ✅ Q-04 → бронь остаётся у дарящего с пометкой «удалено» (R-RES-07).
- ✅ Q-05 → напоминания в MVP только внутри приложения; email — F10.
- ✅ Q-06 → напоминание за 14 и за 3 дня (R-EVT-01).
