# Family Wishlist — нефункциональные требования (NFR)

Статус: черновик · 2026-11-12. Основа: `prd.md`, `permissions.md`, ADR-001…006.
Формат: ID `N-<ОБЛАСТЬ>-<NN>`, модальность RFC 2119. Числа — ориентиры MVP; превышение = баг или осознанный пересмотр.

## 1. Масштаб (расчётные допущения)

| Параметр | Значение |
| --- | --- |
| Семей | ≤ 10 |
| Профилей в семье | ≤ 30 |
| Желаний на профиль | ≤ 500 |
| Одновременных пользователей | ≤ 50 |

Архитектура НЕ ДОЛЖНА оптимизироваться под больший масштаб в ущерб простоте.

## 2. Безопасность

**Доступ**

- **N-SEC-01.** Каждый эндпоинт ДОЛЖЕН проверять права через `authz` по `permissions.md`; каждая ячейка матрицы покрыта тестом.
- **N-SEC-02.** Каждый эндпоинт ДОЛЖЕН иметь тест «данные другой семьи недоступны» (D-01, IDOR).
- **N-SEC-03.** Все входные данные ДОЛЖНЫ валидироваться zod-схемой из `packages/shared`.

**Сессии и токены**

- **N-SEC-04.** Пароли и сессии — только средствами Better Auth (ADR-003); собственная криптография ЗАПРЕЩЕНА.
- **N-SEC-05.** Share-токены и токены гостевых броней: ≥ 128 бит случайности, в БД только хеш (D-08), сравнение за постоянное время.
- **N-SEC-06.** Отозванная ссылка ДОЛЖНА перестать работать сразу, без кеширования доступа.

**Rate limit**

| Действие | Лимит |
| --- | --- |
| Вход | 5 попыток / мин на IP + email |
| Регистрация по приглашению | 10 / час на IP |
| Гостевая бронь | 10 / час на ссылку + IP |
| Разбор ссылки | 30 / мин на пользователя |

- **N-SEC-07.** При превышении система ДОЛЖНА отвечать `429` без раскрытия, существует ли аккаунт.

**Разбор ссылок (F3) — SSRF**

- **N-SEC-08.** Разрешены только `http`/`https` на портах 80 и 443.
- **N-SEC-09.** Запросы к приватным, loopback, link-local и metadata-адресам (IPv4 и IPv6) ДОЛЖНЫ блокироваться; проверка — после DNS-резолва и на каждом редиректе (защита от DNS rebinding).
- **N-SEC-10.** Лимиты: таймаут 5 с, ≤ 3 редиректа, ≤ 2 МБ тела, только `text/html`. JavaScript страницы НЕ выполняется.
- **N-SEC-11.** Извлечённые поля ДОЛЖНЫ санитизироваться; HTML со страницы НЕ ДОЛЖЕН попадать в ответ API.

**Веб**

- **N-SEC-12.** Только HTTPS; HSTS; заголовки безопасности (helmet) и CSP без `unsafe-inline` для скриптов.
- **N-SEC-13.** CSRF: cookie `SameSite=Lax` + проверка `Origin` на изменяющих запросах (ADR-003).
- **N-SEC-14.** Секреты — только в env; в репозитории — `.env.example` без значений.
- **N-SEC-15.** CI ДОЛЖЕН падать на уязвимостях зависимостей уровня high и выше.

## 3. Приватность

- **N-PRV-01.** Данные о бронях ДОЛЖНЫ исключаться на уровне сериализации ответа для субъектов без права (R-RES-01, R-RES-08); тест — на каждый эндпоинт, отдающий желания.
- **N-PRV-02.** Лента, напоминания, уведомления и сообщения об ошибках НЕ ДОЛЖНЫ раскрывать факт брони владельцу (R-FEED-01).
- **N-PRV-03.** Логи НЕ ДОЛЖНЫ содержать пароли, токены, cookie, email и имена гостей.
- **N-PRV-04.** Картинки желаний загружаются с `referrerpolicy="no-referrer"`.
- **N-PRV-05.** Гостю НЕ ДОЛЖНЫ быть доступны данные семьи сверх открытого вишлиста (имена других профилей, другие вишлисты).
- **N-PRV-06.** Удаление аккаунта — по запросу, вручную через admin, в течение 30 дней (GDPR). Удаляются профиль, желания, вишлисты, события; брони, сделанные пользователем, обезличиваются.
- **N-PRV-07.** Ссылка на процедуру удаления ДОЛЖНА быть доступна в настройках профиля.

## 4. Производительность

- **N-PERF-01.** API: p95 ≤ 300 мс для чтения и ≤ 500 мс для записи (без разбора ссылок) при масштабе из раздела 1.
- **N-PERF-02.** Разбор ссылки: ответ ≤ 6 с (таймаут N-SEC-10 + обработка); UI показывает прогресс и не блокирует ручной ввод.
- **N-PERF-03.** Веб: LCP ≤ 2,5 с на мобильном 4G; JS-бандл первой загрузки ≤ 250 КБ gzip.
- **N-PERF-04.** Списки желаний и ленты — с пагинацией, ≤ 50 элементов на страницу.

## 5. Доступность сервиса и данные

- **N-AVL-01.** Цель доступности — 99% в месяц (один инстанс Railway, ADR-002).
- **N-AVL-02.** `GET /api/health` проверяет соединение с БД; внешний мониторинг — каждые 5 мин.
- **N-BAK-01.** Ежедневный `pg_dump` во внешнее хранилище; хранение 14 дней.
- **N-BAK-02.** RPO ≤ 24 ч, RTO ≤ 4 ч. Восстановление проверяется в фазе 5 и затем раз в квартал.
- **N-BAK-03.** Миграции ДОЛЖНЫ быть обратно совместимы с предыдущей версией кода (expand → migrate → contract).

## 6. Наблюдаемость

- **N-OBS-01.** Структурированные JSON-логи (pino) с `request_id` на каждый запрос.
- **N-OBS-02.** Ошибки FE и BE — в Sentry с версией релиза.
- **N-OBS-03.** Метрика успешности разбора ссылок (PRD, раздел 7) ДОЛЖНА собираться: `parse_status` по каждой попытке.

## 7. Интерфейс

- **N-UX-01.** Mobile-first: корректная работа от 360 px ширины.
- **N-UX-02.** Ключевые сценарии (PRD, раздел 6) соответствуют WCAG 2.1 AA.
- **N-UX-03.** Браузеры: две последние версии Chrome, Safari (macOS и iOS), Firefox, Edge.
- **N-UX-04.** Интерфейс на русском и английском. Все строки UI — через i18n-ключи, хардкод текста ЗАПРЕЩЁН. Язык: настройка профиля, по умолчанию — язык браузера, fallback — английский.
- **N-UX-05.** Даты, числа и цены форматируются по локали пользователя (`Intl`); валюта — из желания (Q-10).
- **N-UX-06.** Картинка желания — ссылка на источник; если не загрузилась, показывается заглушка.

## 8. Решения

- ✅ Q-15 → Б: русский + английский, i18n с первого дня (N-UX-04).
- ✅ Q-16 → А: удаление по запросу через admin (N-PRV-06…07).
- ✅ Q-17 → А: храним ссылку на картинку магазина (N-UX-06). Своё хранилище — при необходимости позже.
