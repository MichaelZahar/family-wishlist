# Quickstart: проверка F1 · Auth и семья

Руководство по проверке готовой фичи. Контракт — `contracts/api.md`, данные — `data-model.md`.

## Подготовка

```sh
pnpm install
cp .env.example .env        # если .env ещё нет; задать BETTER_AUTH_SECRET
pnpm db:up
pnpm db:migrate
pnpm dev
```

Web — `http://localhost:5173`. В worktree БД и порты — из `.env.local` (ADR-006, C4).

## Автоматическая проверка

```sh
pnpm lint && pnpm typecheck && pnpm test
pnpm format:check && pnpm build && pnpm e2e
```

Ожидается код 0. Тесты API идут против `DATABASE_URL_TEST`. Сценарий ниже автоматизируется в `e2e/`; вручную он проходится один раз перед merge.

## Проверка изоляции (AC-9)

Только автотестом: под admin семьи А вызвать `DELETE /api/invitations/:id` и `POST /api/family/members/:profileId/password-reset` с идентификаторами семьи Б → `404`; приглашение семьи Б остаётся действующим.

```sh
pnpm vitest run --project api
```

## Проверка логов (N-PRV-03)

После шагов 2–11 в выводе `pnpm dev` нет email, паролей, значений cookie, токенов приглашений и сброса.
